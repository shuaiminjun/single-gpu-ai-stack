# 20 GB 卡上的显存事故与对策

这张纸只记**真的撞过的墙**和当时的判据。硬件：AMD RX 7900 XT / 20 GB / ROCm 7.2.1 / Windows 11。
换成 CUDA 卡，症状里的驱动报错会变，但"谁占着卡"的逻辑是一样的。

---

## 1. 最容易误判的一种：进程直接消失

**现象**：出图请求全部失败，界面上写"连不上 8188"。`curl /system_stats` 也没有响应。

**日志**：

```
LLVM ERROR: Can't get available size
Fatal Python error: Aborted
```

**真相**：ROCm 在显存分配失败时**不抛 Python 异常**，而是把整个进程 abort 掉。
所以不会有 traceback 指向你的代码，只有这两行。

**判据**：先看端口有没有人监听——

```bash
netstat -ano | grep -w 8188 | grep LISTENING     # 空 = 进程真的没了
```

**对策**：不要重装依赖，也不要怀疑模型文件。杀掉残留进程 → **等 12 秒**（GPU 上下文没释放，
立刻重启会再撞一次）→ 重新拉起。要自动化就用 `ops/comfy_watchdog.py`。

---

## 2. 崩溃点根本不在出图，而在"翻译提示词"

**现象**：`/system_stats` 返回 200，`/queue` 里还有任务，但整批请求全部 "connection refused"。
**排查了半天才发现是后端在等一个永远不会结束的任务。**

**真相（两层）**：

1. 中文提示词要先送到一个 4B 文本模型翻成英文。这一步会**临时加载一个大模型**，
   而图像底模（6~7 GB）还占着卡 → 挤爆 → 上面那个 abort。
2. 更阴的是：任务被清出队列后，`/history/<id>` **永远不会有它**。轮询逻辑会一路睡到
   30 分钟超时才返回，把工作线程占死，于是别的请求全被拒。

**对策**：

- 翻译前查一次空闲显存（`/system_stats` 的 `vram_free`），不够就先 `POST /free {"unload_models": true}`；
- 翻译完**立刻再卸一次**，别把 4B 模型留给出图；
- 轮询时同时查 `/queue`：连续若干次既不在 history 也不在 queue，直接判定"任务消失"并立即失败。

---

## 3. 不崩但慢 4 倍：模型互相换入换出

**现象**：1024² 出图从 48 秒掉到 **240 秒/步**，显存看着还剩几 GB。

**真相**：两个框架（ComfyUI 和本地 GGUF 推理）各自占着一个大模型，块在卡和内存之间来回搬。
ComfyUI 的文本编码器只要还在卡上，"看起来够用"其实一直在 swap。

**对策**：

- 出图前把对话模型释放（本项目是 `release_models`），对话前把 ComfyUI 显存收掉；
- ComfyUI 启动加 `--cache-none`：不缓存文本编码器，12B 级别的模型才不会反复换入换出。

---

## 4. `POST /free` 不是万能的

**现象**：调了 `/free {"unload_models": true, "free_memory": true}`，显存只回到 4/20 GB。

**真相**：它只卸"模型缓存"，**不释放 HIP 上下文**。模型加载过一次之后，那部分上下文就一直在。

**对策**：要拿回全部显存只能**杀进程重启**（并等 12 秒）。所以别把 `/free` 当成"清空"。

---

## 5. 出图成功，但产物是纯黑

**现象**：HTTP 200、日志里 `loaded completely` 和 `Prompt executed` 都有，打开图是全黑。

**真相**：不是显存，是 **fp16 在 ROCm 上数值溢出出 NaN**，最后 `clip(...).astype(uint8)` 全变 0。
唯一的线索是日志末尾一行 `RuntimeWarning: invalid value encountered in cast`。

**判据**：**看产物本身**。一张正常图有几千种颜色，纯色/黑图只有个位数。

**对策**：VAE 用 bf16 或 fp32（kohya 侧是 `--no_half_vae`）。

---

## 6. 训练和出图不能同时跑

**现象**：训练跑到一半进程没了，或者训练速度掉一半。

**真相**：底模 6.6 GB + 训练激活 + 出图底模，20 GB 装不下两套。

**对策**：训练前**先停看门狗再停 ComfyUI**（顺序反了看门狗会把它拉回来），训练完等 25~30 秒再启动 ComfyUI。
本项目把这条写进了流水线脚本，避免"忘了停"。

---

## 一句话总结

> 这些事故里没有一次是"代码写错了"，全是**谁在占卡、占了多少、什么时候释放**。
> 判断顺序永远是：端口有没有人听 → 进程在不在 → 显存在谁手里 → 是不是驱动级 abort。
